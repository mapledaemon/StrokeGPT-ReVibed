===========================
StrokeGPT-ReVibed Changelog
===========================

This changelog tracks pull requests made in the StrokeGPT-ReVibed fork, plus
the current unreleased branch only before a pull request exists. Once a branch
has an open PR, its changelog entry should use the PR number instead of
`Unreleased` so follow-up changelog-only PRs are not needed.


2026-05-17 - PR #258 - Smooth Milk Speed Changes And Chat Intensity Arc
------------------------------------------------------------------------

Branch: codex/milk-hsp-jitter-buffering

- Preserve continuous HSP phase ratio when the LLM changes speed on the same
  fixed pattern, so `llm+milk` can vary speed without jumping to a different
  point in the cycle.
- Keep same-pattern speed changes meaningful in chat routing while still
  filtering small depth/range drift from repeated fixed-pattern LLM outputs.
- Add a compact top-bar intensity arc control for steady/ramp-up/ramp-down/
  variable chat guidance, and feed the normal-chat elapsed timer plus an
  explicit `arc` variable into the LLM context once a chat session has begun.
- Guard ordinary chat responses from turning unrequested tight/local LLM moves
  such as `tip+flutter` into abrupt area-focus replacements; preserve the
  current broad pattern and apply only the intended speed change unless the
  user explicitly asked for that focus.
- Add more HSP latency reserve for continuous replacements and expand buffered
  point spacing after slow Handy commands, reducing expired `buf 0.0ms`
  replacement batches that could starve or restart motion.

  of expanding the whole bottom bar.

- Reduce `llm+milk` chat-mode jitter by keeping broad milk commands centered
  and skipping repeated same-pattern LLM replacements caused by small numeric
  noise.
- Prevent a replaced background-mode thread from stopping newer motion or
  clearing the active-mode state if its old cleanup runs late after a slow
  model/device call.
- Stabilize the HSP transport-slope regression test by waiting for trace rows
  to cover the accepted fake-HSP batch before asserting trace-derived rates.

2026-05-13 - PR #184 - Vary Continuous-Backend Speed With Per-Sample Position Rate
-----------------------------------------------------------------------------------

Branch: claude-continuous-speed-per-sample

- Diagnosed an on-device observation that motion speed appeared fixed
  across one pattern playback while only the position pattern varied:
  the default ``continuous`` backend's sampler
  (``_motion_target_for_sample`` via ``sample_continuous_plan``) was
  returning ``speed = target.speed * style.speed_scale`` verbatim for
  every HDSP frame, so every sample inside one cycle ran at the same
  speed. PR #182 had already taught ``_actions_to_frames`` to lift
  per-frame speed when ``preserve_timing=True`` (the Motion Pattern
  Studio's imported-pattern preview), but the continuous backend's own
  sampler never got that boost -- regular chat-driven motion stayed
  flat.
- Compute a short-window position derivative inside
  ``sample_continuous_plan`` (``SAMPLE_DERIVATIVE_DT_SECONDS = 0.04``,
  re-using the cyclic Catmull-Rom sampler at ``phase`` and ``phase +
  dt / duration``) and forward it as a new keyword-only
  ``position_per_second`` argument to ``_motion_target_for_sample``.
  When provided, the per-sample speed lifts to
  ``max(base_speed, clamp((position_per_second / 160) * 100, 8, 100) *
  style.speed_scale)`` -- the exact boost formula
  ``_actions_to_frames`` already applies. Slow segments fall back to
  the LLM-supplied base speed; fast segments lift above it so the
  device feels a difference between a slow hold and a quick climb.
- Opt-in via keyword arg defaulting to ``None``: only
  ``sample_continuous_plan`` passes it. Every other direct caller of
  ``_motion_target_for_sample`` keeps its prior behavior, so motion-
  training Studio preview, anchor-program playback, and the existing
  test surface are unaffected.
- Added four contract tests in ``tests/test_motion_scripts.py``:
  helper-level no-hint / slow-hint / fast-hint speed behavior, the
  ``style.speed_scale`` interaction with the boost, the asymmetric
  ``ramp`` plan produces a varied speed track across one cycle
  (>=5%-point spread, replacing the prior flat constant), and the
  symmetric ``hold`` plan never drops below the LLM-supplied base
  speed even when the local derivative is small. Total suite 406 ->
  410.

2026-05-10 - PR #146 - Smooth Continuous Motion Sampler (Wrap + Catmull-Rom + Jitter)
------------------------------------------------------------------------------------

Branch: claude-continuous-motion-fluidity

- Quality review of the continuous motion backend that PR #118 shipped.
  The phase-sampled control loop, generation-counter cancellation,
  morph-in easing, velocity capping, and per-tick step limiting are all
  solid. The sampler itself had three real gaps that this branch
  addresses, all in `strokegpt/motion_patterns.py`:

  1. Per-cycle position step at phase wraparound. The previous cosine
     sampler returned `actions[-1].pos` at phase=1.0 and
     `actions[0].pos` at phase=0.0. An audit of the built-in catalog
     showed 30 of 34 patterns are asymmetric (e.g. `ramp` runs 20 ->
     100, `milking-pressure-build` runs 12 -> 92), so almost every
     pattern hit a hard position jump once per cycle. The controller's
     `_limit_continuous_step` clamped that jump into a series of small
     steps, but the perceived rhythm was still mechanical.
  2. Cosine-only interpolation between adjacent actions. Cosine
     produces a velocity discontinuity at every action boundary
     (C^0 but not C^1). Catmull-Rom across four neighbors was already
     used by `prepare_anchor_actions` for anchor programs, but the
     live continuous sampler stuck with cosine.
  3. Style depth/range jitter declared on `FrameStyle` was never
     applied. `_motion_target_for_sample` ignored `style.depth_jitter`
     and `style.range_jitter`. Patterns that opted into jitter got
     none in continuous mode, which kept the sampled output
     metronomically periodic.

- Three concrete changes in `strokegpt/motion_patterns.py`:
    - New `_wrap_segment_ms(actions)` returns a per-cycle wrap span in
      milliseconds scaled by the position delta between
      `actions[-1].pos` and `actions[0].pos`. Closed patterns get a
      near-flat 50 ms floor; open patterns scale up so the controller
      has time to glide through the gap instead of slewing. The plan
      cycle duration and phase sampler both use
      `(actions[-1].at - actions[0].at) + wrap_ms`, so the wrap segment
      gets real elapsed time instead of compressing the authored action
      spans.
    - `_sample_action_position(actions, phase)` rewritten to sample
      via cyclic Catmull-Rom across four neighbors. Walks a cumulative-
      time table that includes the wrap segment, so every position in
      `[0, total_cycle_ms)` maps to a smooth phase-domain curve.
      Catmull-Rom's <=12.5% overshoot is clamped to [0, 100] so a spike
      at stroke top/bottom never sends the controller an out-of-range
      depth.
    - `_motion_target_for_sample` now applies smooth time-based jitter
      via a new `_smooth_jitter(jitter_phase, amount, axis_seed)`
      helper. Two sine waves at near-irrational frequency ratio
      (2.3 and 3.7 times tau) sum to a bounded perturbation that
      varies smoothly with `jitter_phase` and never perfectly repeats.
      Depth and range use decorrelated `axis_seed` values so they
      drift independently rather than in lockstep. Zero-amount
      jitter is a no-op.
    - `sample_continuous_plan` computes a `jitter_phase` from
      `elapsed_seconds % JITTER_CYCLE_SECONDS` (5 s) so jitter is
      decoupled from the pattern cycle. Pattern cycle and jitter cycle
      drift in and out of phase, which feels organic rather than
      synchronized.

- 10 new behavioral tests in `tests/test_motion_scripts.py`:
    - `_sample_action_position` is phase-cyclic (phase~1.0 ~~ phase~0.0).
    - No single-step position jump exceeds ~6 units on a 200-sample
      sweep of an asymmetric pattern (the previous cosine sampler
      failed this with ~60-unit jumps at the wrap).
    - Sampler clamps to [0, 100] under Catmull-Rom overshoot conditions.
    - `_smooth_jitter` is bounded, deterministic, zero on zero/negative
      amount, and decorrelated across `axis_seed` values.
    - `_motion_target_for_sample` applies jitter when `style` declares
      it and stays identical with `style.depth_jitter ==
      style.range_jitter == 0`.
    - `sample_continuous_plan` produces distinct depth/range values at
      the same pattern phase but different `jitter_phase`.

- No new dependency. No behavior change for cosine-using callers
  (there are none -- only `sample_continuous_plan` used the sampler,
  and the `interpolation` parameter was always `"cosine"`; removed the
  unused parameter). Existing
  `test_continuous_motion_plan_samples_pattern_as_cycle` still passes
  against the new sampler.

- Validation: `python -m unittest discover -s tests` green at 336 /
  111 skipped (was 326 / 111 -- +10 new sampler tests). `python -m
  py_compile app.py strokegpt/*.py tests/*.py` clean.

- Follow-ups deferred to keep this branch focused:
    - Adaptive `CONTINUOUS_MORPH_SECONDS` scaling with depth-jump
      magnitude in `motion.py`'s `_run_continuous_plan`.
    - Phase continuity across target updates (currently each new
      target resets the pattern cycle to phase=0; the morph easing
      covers most of the visible effect, but preserving phase would
      make same-pattern speed/depth tweaks even more seamless).
    - Cache `program_range` on the plan instead of resampling 25
      points every time `_run_continuous_plan` starts (minor perf).

2026-05-10 - PR #114 - Auto-Detect ASR Device + Compute Type
----------------------------------------------------------------

Branch: claude-voice-asr-auto-device

- Continues ROADMAP #13 ASR work order step 1 ("auto-CUDA/device
  detection, compute-type selection") after PR #108 landed the
  confidence + beam-1 fast path. Same goal: cut the live mic latency
  for users who already have the hardware to run faster transcription,
  without expanding the Settings > Voice surface that is already too
  knob-heavy.
- Two new helpers in `strokegpt/asr.py`:
    - `_count_cuda_devices()`: lazy-imports `ctranslate2` and returns
      the number of visible CUDA devices, defensively returning `0` on
      any import or runtime failure (broken CUDA libs, missing wheel).
    - `_detect_device(env_value)`: honors an explicit
      `STROKEGPT_ASR_DEVICE` override (case- and whitespace-insensitive,
      including pinned indices like `cuda:1`) and falls back to
      `cuda` when CUDA is visible, `cpu` otherwise.
    - `_detect_compute_type(env_value, device)`: honors
      `STROKEGPT_ASR_COMPUTE_TYPE` override; auto picks `float16` on
      CUDA (~2x faster than int8 at similar Whisper accuracy) and
      `int8` on CPU (smaller memory, AVX2-friendly).
- `_load_model()` now calls the two helpers instead of reading the env
  vars directly with `cpu`/`int8` defaults. The chosen device +
  compute_type prints to stdout once at model load
  (`[INFO] faster-whisper loading model='small.en' device=cuda
  compute_type=float16`), so the speedup is visible to the user
  without needing to enable diagnostics.
- Behavior change is opt-out, not opt-in: the previous defaults
  (`cpu`/`int8`) are now the *fallback* when no CUDA is visible. Users
  who had `STROKEGPT_ASR_DEVICE=cpu` or `=cuda` set explicitly keep
  exactly their previous behavior. Users who had nothing set get
  auto-CUDA the next time the model loads, which is the ~10x latency
  cliff the roadmap called out as the "single biggest ASR latency win
  for users who happen to have NVIDIA hardware."
- No new dependency: `ctranslate2` is already a transitive dep of
  `faster_whisper`. The helper imports it lazily inside the function
  body, matching the existing `from faster_whisper import WhisperModel`
  pattern, so this slice does not change CPU-only install footprint.
- No Settings > Voice change. ROADMAP #13 explicitly says "Treat
  faster-whisper baseline tuning as backend behavior first, not
  another Settings > Voice expansion"; this slice obeys that.
- Tests in `tests/test_asr.py`:
    - `DeviceDetectionTests` (6): explicit values honored
      case/whitespace-insensitively, GPU index pin-through, auto
      branches based on a mocked `_count_cuda_devices`, empty/None
      treated as auto.
    - `ComputeTypeDetectionTests` (6): explicit honored, auto +
      `cuda`/`cuda:N`/`cpu`/unknown device picks the right
      compute_type, unset/None treated as auto.
    - `CountCudaDevicesTests` (2): defensive zero on

      scenario), and integration check that mock-returned counts pass

Branch: claude-frontend-test-runner

- Closes the Backlog #13 "Frontend Test Runner For Behavioral JavaScript

  driven via a Python skip-if-missing wrapper. Rejected alternatives:
  Vitest + jsdom (adds full Node ecosystem, ~150MB `node_modules`,
  conflicts with the no-Node-toolchain repo philosophy);
  `py_mini_racer`/`pythonmonkey` (~50MB binary, dormant maintenance,
  custom DOM still required); translating JS logic to Python (does not
  exercise the JS). The picked option adds zero new repo dependencies:
  no `package.json`, no `node_modules`, no `requirements.txt` entry.
- New files:
    - `tests/js/_harness.mjs`: a deliberately minimal DOM stub that
      installs `globalThis.document`, `globalThis.window`,
      `globalThis.navigator`, plus `MediaRecorder`/`FormData`/`Blob`
      placeholders so production browser ES modules can evaluate without
      a real browser. Loaded via `node --import` so the stub is in place
      before any production module's top-level
      `document.getElementById(...)` runs (see `static/js/context.js`).
      The leading underscore keeps `node --test` from auto-discovering
      it as a test file.

      called for. Drives `updateActiveModeTimer` through stop and

      the frozen elapsed timecode (`00:42`), not `00:00`; new-mode start

      back near 0 also resets. Five scenarios total, mirroring the
      source-text invariants in `tests/test_motion_status_log_timecodes.py`.
    - `tests/test_frontend_runtime.py`: skip-if-missing Python wrapper
      that subprocesses `node --import file://.../_harness.mjs --test
      <test files>`. Skips when Node is not on PATH or when Node is
      below version 20. The harness path is passed as a `file://` URI
      via `Path.as_uri()` for cross-platform ESM resolution. The
      wrapper enumerates `*.test.mjs` files in Python and passes each
      as an explicit argument to `--test`; older Node accepted a
      directory argument but Node 24 dropped that and treats a
      directory as a module-import target, failing with
      `ERR_UNSUPPORTED_DIR_IMPORT`. Surfaces the Node runner
